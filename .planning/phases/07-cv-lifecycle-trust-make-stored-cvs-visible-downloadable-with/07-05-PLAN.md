<interfaces>
Inngest 4.4.0 supports function-level timeouts — VERIFIED against
node_modules/inngest/types.d.ts:1461. Config shape:
  timeouts?: { start?: DurationString; finish?: DurationString }
DurationString is the templated `${number}m` / `${number}h` / `${number}d`
family (e.g. '5m', '10m', '1h').
  * `start`  — cancel the run if it has not STARTED within the window. On a
    concurrency-1 cron this is what stops ticks piling up behind a blocked
    slot.
  * `finish` — cancel the run if it has not FINISHED within the window after
    starting. This is what releases a wedged slot.
A cancelled run emits `inngest/function.cancelled`.

Heartbeat prior art — copy this shape exactly, it is already proven in two
functions:
  refresh-outlook-subscription.ts:49
    Sentry.captureMessage('outlook:cron:heartbeat', {
      level: 'info',
      tags: { layer: 'inngest', function: 'refresh-outlook-subscription' },
    })
  stripe-reconcile.ts:93
    Sentry.captureMessage('phase5:stripe-reconcile:heartbeat', {
      level: 'info',
      tags: { phase: 'p5', layer: 'inngest', function: 'stripe-reconcile' },
    })
Both fire at the TOP of the handler, BEFORE any step.run, so the signal is
emitted even on a run that finds nothing to do. That is the whole point.

Current config of the two targets:
  embed-batch:          triggers cron 'TZ=Europe/London */10 * * * *' + event
                        'embed/backfill-org'; concurrency {limit:1}; retries 1
  reconcile-cv-parses:  triggers cron 'TZ=Europe/London */15 * * * *';
                        concurrency {limit:1}; retries 1
</interfaces>

The spec-hardening bar this new spec must meet — every one of these is a real
lesson already paid for in cv-intake.smoke.ts and re-learned during its
2026-08-10 review. Read that file before writing a single line:
  * fail-closed org guard: SMOKE_ALLOWED_USER_ID is REQUIRED, the session's
    JWT `sub` is decoded from the storageState cookie and compared, and the
    spec REFUSES to run on a mismatch or a missing var (lines 44-74, 192-207).
    This spec writes real rows in a real org — it must never run under a
    session that may belong to a customer.
  * hydration-aware locators: pages hydrate AFTER 'load', so a one-shot
    count() silently sees zero. Always waitFor the control, or race a
    positive locator against the empty-state locator (lines 225-254). Two
    separate delete paths were silently skipped by exactly this bug.
  * prefix-sweep cleanup in afterAll that deletes ANY row matching the scratch
    prefix (not just the ones this run tracked, because a serial-mode failure
    leaves orphans), then RE-ASSERTS via a fresh server round-trip that nothing
    matching the prefix survives. Residue is itself a failure.
  * scope role queries: sonner toasts portal to body level and carry
    role="alert" — always scope to page.locator('main') (line 112).
  * import load-bearing app copy from the source module rather than
    hand-copying string literals (lines 10-13).
  * track a created entity BEFORE any assertion that could throw (line 278).
  * assert zero uncaught pageerrors across the whole run (line 364).

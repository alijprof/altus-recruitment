<objective>
Make every stored CV file reachable from the candidate page — filename, upload
date, and a working View link on every CV row — and audit each access.

Purpose: The CV files have existed in private Storage since Phase 1 and tenant
SELECT is already granted (migration 20260517204501:17-22), but NO UI anywhere
exposes them. The customer's #1 trust complaint is "I can't see the CV you're
holding for me." This is a pure UI + one-server-action gap. Implements D-01.

Output: A `CV files` section listing every `candidate_cvs` row, a signed-URL
server action, and an `export` audit row per access.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → getCvFileUrlAction | Recruiter-supplied `candidateCvId` is untrusted input |
| app → Supabase Storage | Signed URL grants unauthenticated bearer access to a PII document |
| app → audit_log | The compliance record of who read what |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Information disclosure | getCvFileUrlAction | mitigate | Two independent tenancy gates: `getCandidateCV` under the RLS-scoped SSR client (cross-tenant id → not_found) AND the `Tenant select own org CVs` Storage policy keyed on `(storage.foldername(name))[1] = current_organization_id()` |
| T-07-02 | Information disclosure | signed URL lifetime | mitigate | 60s TTL matching apply/actions.ts:155; URL is opened immediately and never persisted, logged or embedded in markup |
| T-07-03 | Repudiation | CV download | mitigate | `action='export'` audit awaited BEFORE the URL is returned; `export` is excluded from the record_audit hourly dedupe so every access is a distinct row |
| T-07-04 | Information disclosure | Sentry / audit metadata | mitigate | storage_path embeds a slugified candidate name — it is never sent to Sentry and never written to audit metadata; metadata is ids + integer version only |
| T-07-05 | Elevation of privilege | direct action invocation | mitigate | `auth.getUser()` check plus the server-side `isCvFileDownloadable` mirror of the UI's disabled state |
| T-07-06 | Tampering | npm/pip/cargo installs | accept | This plan adds NO dependencies; nothing to audit |
</threat_model>

Default vitest include (not overridden in `vitest.config.ts`) is
`['**/*.{test,spec}.?(c|m)[jt]s?(x)']`. A file named `*.forensic.ts` is therefore
NEVER collected by `pnpm test`. That is the isolation mechanism — do not add an
`exclude` entry for it (that would edit `vitest.config.ts`, which this phase
deliberately leaves untouched).

`vitest.config.ts` today:
```ts
export default defineConfig({
  plugins: [tsconfigPaths(), react()],
  test: {
    environment: 'jsdom',
    globals: true,
    setupFiles: ['./tests/setup.ts'],
    exclude: ['**/node_modules/**', 'tests/e2e/**', '.next/**', 'dist/**', 'chrome-extension/dist/**'],
  },
})
```

Verified Postgres 17.6 + PostgREST v14.5 behaviour the classifier must encode
(06-RESEARCH.md §"Verified failure matrix" — treat as ground truth, do not
re-derive):

| Payload condition | Code |
|---|---|
| `U+0000` in any string VALUE reaching a jsonb/text/text[] column | `22P05` |
| `U+0000` in any object KEY reaching a jsonb column | `22P05` |
| lone UTF-16 surrogate anywhere in the payload | `PGRST102` (PostgREST layer, no SQLSTATE) |
| `salary_current_estimate`/`salary_expectation` non-numeric string, float, object or array | `22P02` |
| `salary_*` numeric but `> 2147483647` | `22003` |
| `years_experience_total` absolute value `>= 1000` | `22003` (column is `numeric(4,1)`) |
| `years_experience_total` non-numeric string | `22P02` |
| `skills`/`sector_tags` as a 2-D array | `22P02` |
| `name` present but not a string | `TypeError` (JS, before the DB) |
| `work_history` containing a `null`/non-object element | `TypeError` (JS, before the DB) |
| `skills` as an array of OBJECTS | **no error** — silently stored as `{"name":"Python"}` (Tier-3 data corruption, must be reported as a WARN not a failure) |
| control chars `U+0001`–`U+001F` other than NUL, emoji, ZWJ, astral plane, RTL, BOM, 1.1 MB values | **legal** — must NOT be flagged |

Lone-surrogate regex (ES2018 lookbehind, verified to run on Node 24):
`/[\uD800-\uDBFF](?![\uDC00-\uDFFF])|(?<![\uD800-\uDBFF])[\uDC00-\uDFFF]/g`

    - `work_history: [null, {role:'Dev'}]` → `rule: 'work-history-null-element'`, `code: 'TypeError'`.
    - `skills: [['a','b']]` → `22P02`; `skills: [{name:'Python'}]` → `severity: 'warn'`, `rule: 'skills-object-elements'`, `code: null` (silent corruption, NOT a write failure).
    - `classifyForPostgres({})` returns zero findings.
    - No finding ever carries a payload VALUE — only `rule`, `path`, `code`, `severity` and, for numeric fields only, the offending number.
  </behavior>

    ```
      code: PgLegalityCode

    ```

<objective>
Make every asynchronous failure honest. Today a corrupt PDF, a truncated file, a
password-protected PDF and a wrong-extension upload all land as
`CV_PARSE_FAILED_MESSAGE` ("Parsing failed. You can retry now…") with a retry
button that can never succeed — a Tier-2 and Tier-3 violation living in the code
independently of the 12. And `parse_error_detail` records `Error: undefined`
because the SQLSTATE was discarded three frames earlier.

Purpose: close the "no third outcome" contract from the customer-visible goal —
every upload either parses OR fails with an honest, actionable message.

Output: new message literals and predicates, an extraction-error classifier, the
wiring in `parse-cv.ts`, and both halves (UI + server action) of the
no-doomed-retry guard.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Inngest event → service-role Storage read | A forged event could redirect the service-role client at another tenant's bytes |
| library error → `parse_error_detail` (stored) | Library errors can carry file content |
| stored `parse_error` → recruiter UI | Whatever is stored is rendered verbatim |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-24 | Elevation of Privilege | `parse-cv.ts` tenant-boundary check | mitigate | Left byte-identical and outside `step.run`; enforced mechanically by a `git diff` gate in Task 2's verify (ASVS V4) |
| T-06-25 | Information Disclosure | `parse_error_detail` | mitigate | Only `${code}` + column/subop and `extract-text: ${err.name} (${mime})`; never `err.message`, which PostgREST populates with the offending value; unit-asserted in `extraction-errors.test.ts` |
| T-06-26 | Information Disclosure | `parse_error` rendered verbatim in the UI | mitigate | `parse_error` may only ever hold one of the exported constants — the new literals preserve that invariant, so the panel stays PII-safe by construction |
| T-06-27 | Spoofing | direct `retryParseAction` call bypassing the UI guard | mitigate | Server-side refusal keyed off the same shared predicate, placed before the status reset |
| T-06-28 | Tampering | copy edit silently breaking a predicate | mitigate | Every load-bearing substring is asserted in `parse-messages.test.ts`; new literals are checked not to contain `AI budget`, which would hijack the reconciler's auto-resume query |
</threat_model>

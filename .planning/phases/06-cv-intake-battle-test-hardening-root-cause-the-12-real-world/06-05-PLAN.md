`DbResult` today (`src/lib/db/types.ts`):
```ts
export type DbResult<T> =
  | { ok: true; data: T; noop?: boolean }
  | { ok: false; code: 'not_found' | 'internal' | 'duplicate' }
```
Plan 06-06 widens the failure variant with an optional `detail?: string` carrying
the SQLSTATE plus the offending column — asserted by the tests written here.

Verified outcomes these tests must reproduce (06-RESEARCH.md failure matrix):
- NUL in `extracted_data` jsonb (value, key, or nested) → `{ok:false, code:'internal'}`, Postgres `22P05`
- lone surrogate anywhere in the jsonb → `{ok:false, code:'internal'}`, PostgREST `PGRST102` (never reaches Postgres, so a SQLSTATE-only classifier misses it)
- `salary_current_estimate: '£45,000'` → `22P02`; `45000.5` → `22P02`; `3000000000` → `22003`
- `years_experience_total: 2015` → `22003` (`numeric(4,1)`; the cliff is exactly 1000)
- `name: ['Jane','Doe']` → `TypeError: (args.parsed.name ?? "").trim is not a function`, thrown UNCAUGHT out of the helper
- `work_history: [null, {...}]` → `TypeError: Cannot read properties of null (reading 'role')`

Verified NOT to fail — must not be "fixed" or mangled: 1.1 MB string values,
~2 MB `extracted_data`, emoji/ZWJ/astral plane/RTL/CJK/BOM/soft hyphen,
control chars `U+0001`–`U+001F` other than NUL, `'45000'` as a numeric string,
`999.9` years.

Silent-corruption case (writes OK, corrupts data — a Tier-3 violation):
`skills: [{name:'Python'}]` is stored as the text `{"name":"Python"}`.

Trigger note: `candidate_cvs` has a `candidate_cvs_set_org` BEFORE INSERT trigger
using `current_organization_id()`, which returns NULL under service-role with no
session — so the harness MUST pass `organization_id` explicitly when seeding
(this is exactly why `createCandidateCV` has an `organizationId` escape hatch).

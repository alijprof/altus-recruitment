<objective>
Add the Option-A "card-first" access gate. Today a no-subscription org gets the full CRM and Pro-tier AI forever — there is NO paywall. The founder's model: a customer must enter a card (which starts the existing 14-day Stripe trial) before the app unlocks. Stripe already does "14-day trial → auto-charge unless cancelled" in the existing `/api/stripe/checkout` flow. This plan adds ONLY the access gate. No Stripe changes, no new migrations, no webhook changes.

Gating is pure status-based: an org is entitled iff `getEntitlement(...).status` is `'trialing'` or `'active'`. Statuses `'none'`, `'cancelled'`, `'past_due'` are gated.

Purpose: Stop giving the product away for free; force card-up-front trial start.
Output: One new server component (`paywall-screen.tsx`) and a modified app layout (`layout.tsx`) that returns it when the org is not entitled.

IMPORTANT (do NOT implement here — deploy-time note): Existing production orgs (including the founder's own) are currently `status 'none'` and would be gated by this change. They will be grandfathered via a SEPARATE comp-subscription DB step at deploy time (insert a `subscriptions` row with `status 'active'` / a trial_end_override), NOT in this plan. This plan is pure status-based gating with no exception list baked in.
</objective>
